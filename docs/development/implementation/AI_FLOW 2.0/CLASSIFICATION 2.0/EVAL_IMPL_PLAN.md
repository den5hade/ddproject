## 0. Overview

**Current (as-is):** classifier is implemented and pipeline-wired; the only accuracy proxy is a hardcoded recall gate `≥ 0.95` in `tests/unit/classification/test_regression_dataset.py:66`. No metrics code exists. Manifest expectations were generated by running the M2 classifier over each fixture (descriptive, not aspirational — `manifest.json` notes "recalibration in M3 may update them"). M2 locked scoring constants are explicitly "calibrated in M3":

```text
confidence = clamp01(0.6*dominance + 0.4*strength)   STRENGTH_REF=20.0
level = HIGH ≥0.90 / MEDIUM ≥0.70 / LOW <0.70
decision: FALLBACK top<5.0 → other · AMBIGUOUS margin<0.25*top · else ACCEPT
client hint +5 (strong); contradicting −4
```

M2 flagged issues awaiting M3 evidence: confidence **saturates at 1.00** on unambiguous real markers (dominance=1.0), biochemistry detector over-fires on assay-description phrases ("сыворотке или плазме крови"), Helix marker has `subtype=None` (candidate `microbiology`), `lab_without_keywords_001` is the intentional false-generic probe.

**Target (M3):**

```text
tests/fixtures/classification/ (11, ground-truth audited)
  → evaluate.py (loader + metrics, deterministic, offline)
        ├── per-fixture verdict (expected vs predicted, scores, margin, signals)
        ├── summary (accuracy, per-type P/R/F1, macro/micro)
        ├── domain rates (wrong_schema / generic / ambiguous / false_laboratory, with counts)
        └── confidence calibration (distribution, saturation, reliability-by-band)
  → evidence → calibration (scoring.py / signals/*, version 2.1.0)
  → count-based regression gates (test_regression_dataset.py, test_evaluate.py)
  → eval report artifact + IMPL_PLAN M3 addendum
```

**Key mechanisms:** single deterministic evaluation path (`MarkdownNormalizer → detectors → RuleScoringEngine → decision tuple`); a fixture loader owned by the **app** (tests delegate to it) so `evaluate.py` is not a test-side script; every calibration change cites a report finding; gates below `0.1` thresholds are expressed as counts.

**Invariants (locked):**
- Evaluation is deterministic + offline: `python -m app.classification.evaluate` on fixed fixtures must be reproducible run-to-run; no LLM, no network, no storage writes.
- Format-dataset boundary: the evaluate CLI is a dev tool. It must **not** write to S3/RabbitMQ or mutate pipeline state; the report is local output (stdout / `--json` / `--report`).
- `expected_*` in `manifest.json` is **ground truth**, not a projection of classifier output. Any manifest change must be a label correction, not "make the test pass".
- Every calibration change that alters classification output → `classifier_version` minor bump (`2.0.0 → 2.1.0`), per M1 §7 policy. Patch = docs/comments only.
- No calibration change without a finding in the Phase 3 report (anti over-fitting guard — N=11 makes over-tuning the top risk).
- Legacy `classify_document_type` and its tests remain untouched (user decision), even though the pipeline no longer calls it.

## 7. Notes & conventions

### Gotchas (verified)
- `manifest.json` `expected_*` currently encodes M2 classifier behavior (phase 5 note, `IMPL_PLAN.md:134`) — the Phase 2 audit is the point where these become ground truth; flip labels with a stated rationale, not silence.
- Confidence saturates at 1.00 on unambiguous real markers (`IMPL_PLAN.md:103`) — relevant to Phase 3 only if the report shows it hides meaningful gradation; it is expected for clear documents.
- `helix_3` has `subtype=None`; a Phase 3 `microbiology` subtype is a real candidate but changes manifest + subtype rule together.
- `make lint` runs `uvx ruff check apps packages tests`; Phase 4 touches only `apps/ai-worker` + root Makefile.
- Legacy `classify_document_type` + `test_classifier.py` stay green — do not "fix" or remove them in M3 (user decision).

### Open decisions (defaults chosen)
- **Dataset expansion:** wait for more real `marker.md`s; no synthetic negatives in M3. Default chosen (evaluation gates in counts until N > ~50).
- **Calibration width:** conservative, findings-only; keep `0.90/0.70`, `SCORE_FLOOR`, `0.25` margin, client-hint +5 unless a report line forces a change. Default: keep.
- **`biology` subtype:** add only if the Helix report line supports it. Default: defer.
- **Report artifact location:** `apps/ai-worker/reports/classification-eval-<yyyymmdd>.md` (gitignored-friendly, produced by `--report`). Default chosen.
- **Regression gate style:** counts over percentages at N=11 (design-spec §30 rates resume later). Default chosen.

### Risks (mitigations in place)
- **Over-tuning on 11 documents** is the top M3 risk — mitigated by the findings-citation rule (Phase 3) and count-based gates that only assert what the dataset can actually support.
- **Manifest flipped to "make tests pass"** — mitigated by the ground-truth invariant in §0 and the audit rationale recording in Phase 2.
- **Version drift between constants/tests/report** — mitigated by the lockstep rule (Phase 3: `scoring.py` + locked-constant tests + `test_pipeline.py:135` + manifest change together).
- **Eval crossing into pipeline state** — mitigated by the offline/dev-only invariant in §0 (no S3/RabbitMQ/DB in `evaluate.py`).
- **Baseline regression** (M2 fixtures currently 11/11 recall) — each phase re-runs `test_regression_dataset.py` before flipping status.

### Conventions
- Follow `docs/development/CONTRIBUTING.md`; keep changes localized to `apps/ai-worker/app/classification/` (`evaluate.py`, `fixtures` loader, `scoring.py`, `signals/*`, `service.py`), `apps/ai-worker/tests/**`, root `Makefile`.
- Deviations from this plan, if any, are labeled `Deviation:` in a phase's Implementation Status paragraph when signed off.
