Контрастивные языковые модели (Contrastive Language Models, CLM) — это специализированный класс моделей искусственного интеллекта, которые оценивают и ранжируют возможные действия для заданной ситуации с помощью векторных представлений (эмбеддингов), а не генерируют текст посимвольно.
## Как это работает

* Двухэнкодерная архитектура: Использует две независимые проекционные головы или энкодера (один для текущего состояния, другой — для возможных действий), которые работают поверх общей «замороженной» базовой модели (например, энкодера Qwen3).
* Контрастивное обучение: Модель обучается с использованием функции потерь InfoNCE. Ее цель — сблизить в векторном пространстве правильные пары «состояние — действие» и отдалить друг от друга неподходящие варианты.
* Отсутствие генерации текста: Модель ничего не пишет. Вместо этого вы передаете ей описание ситуации и список возможных действий, а она возвращает этот список, отсортированный по степени соответствия.

## Ключевые преимущества

* Высокая скорость и эффективность: Эмбеддинги состояний и действий можно кэшировать и использовать повторно. Это снижает задержку (latency) до 9 раз по сравнению с классическими генеративными моделями на таких задачах, как игры, вызовы ИИ-инструментов (tool-calling) и управление компьютером.
* Эффективная верификация: Специально дообученные варианты (такие как выпущенная модель [CLM-v0.1-8B](https://huggingface.co/Contrastive-LM/CLM-v0.1-8B)) показывают передовые результаты (SOTA) в качестве быстрых верификаторов для сложных многошаговых задач и написания кода.
* Отличие от казуальных моделей: В отличие от стандартных казуальных моделей семейства GPT, которые предсказывают следующий токен для написания текста или кода, CLM занимается исключительно оценкой и маршрутизацией готовых вариантов.

Модель [CLM-v0.1-8B](https://huggingface.co/Contrastive-LM/CLM-v0.1-8B) разработана исследователями из Стенфорда и NVIDIA как открытая альтернатива коммерческой системе TypeSafe AI "Jev". Это System One модель, которая идеально подходит для задач классификации, так как она не генерирует текст, а вычисляет сходство между «состоянием» (документом) и «действиями» (категориями/классами) в едином векторном пространстве. [1, 2, 3, 4] 
Для задачи классификации медицинских документов по нормализованному Markdown это дает колоссальное преимущество в скорости (до 9–13 раз быстрее обычных LLM) и полную независимость от сторонних API, так как веса открыты под лицензией Apache-2.0. [4, 5, 6]

## Архитектура CLM-v0.1-8B
Модель использует замороженную основу Qwen3-8B и обучаемые проекционные головы (всего на 20 млн параметров). Архитектура разделена на два потока: [2, 4] 

   1. State Encoder (Энкодер состояния): Принимает ваш Markdown-документ.
   2. Action Encoder (Энкодер действий): Принимает названия или описания медицинских классов. [7] 

## Как устроена интеграция в ваше приложение
Официальный сервер clm-serve из [репозитория Contrastive-LM на GitHub](https://github.com/Contrastive-LM/CLM) предоставляет совместимый API, поддерживающий три типа запросов: Noul (вероятность True/False), Score (оценка по рубрике) и Choice (выбор из декларативного множества). Именно Choice нужен для вашей классификации. [3, 8] 
## Шаг 1: Развертывание инференса
Вы можете запустить модель локально или на собственном сервере с помощью Docker/Python, либо использовать оптимизированный порт CLM на MLX для локальной работы на Mac (работает со скоростью ~336 токенов/сек). [2, 9] 
Запуск стандартного HTTP-сервера:

pip install contrastive-lm
clm-serve --model Contrastive-LM/CLM-v0.1-8B --port 8000

## Шаг 2: Кэширование классов (Action Vectors) — Секрет скорости
Так как медицинские категории (например: «Кардиология», «Неврология», «Выписка из анамнеза») фиксированы, clm-serve позволяет один раз прогнать их через Action Encoder и сохранить векторы в GPU-кэш. При поступлении нового Markdown-документа модель кодирует только сам документ и мгновенно делает скалярное произведение с кэшированными векторами классов. [5, 8] 
## Шаг 3: Запрос классификации из кода (Пример на Python)
Вы отправляете POST-запрос на сервер CLM. В поле state передается нормализованный Markdown, а в choices — массив возможных медицинских классов.
```python
import requests
# Ваш нормализованный медицинский документ
markdown_document = """
# Выписной эпикриз
**Пациент:** Иванов И.И., 45 лет.
**Диагноз основной:** ИБС. Стенокардия напряжения II ФК.
**Рекомендации:** Прием ацетилсалициловой кислоты 75 мг, контроль АД."""
# Список классов, по которым нужно категоризировать документ
medical_classes = [
    "Кардиология",
    "Неврология",
    "Гастроэнтерология",
    "Травматология и ортопедия",
    "Онкология"
]
payload = {
    "state": markdown_document,
    "question": "К какому медицинскому направлению относится этот документ?",
    "type": "choice",
    "choices": medical_classes,
    "temperature": 0.0  # Для жесткой и точной классификации
}
response = requests.post("http://localhost:8000/v1/predict", json=payload)result = response.json()
# Модель возвращает вероятности (probabilities) для каждого класса через Softmax
print("Результат классификации:")for choice, prob in zip(result["choices"], result["probabilities"]):
    print(f"{choice}: {prob:.4f}")
```
## Архитектурные рекомендации для мед. документов

* 
* Длина контекста: Базовый Qwen3-8B отлично справляется с длинными текстами. Однако для максимальной точности структуры Markdown лучше стандартизировать (например, оставлять только значимые секции: # Жалобы, # Диагноз, # Назначения). [2] 
* Разделение сущностей: Если вам нужно классифицировать документ по нескольким осям одновременно (например, Тип документа и Медицинская специальность), делайте два раздельных независимых запроса Choice параллельно. Благодаря независимому кэшированию векторов это отработает за миллисекунды. [5]
